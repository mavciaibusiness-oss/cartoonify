## Execution summary

This task implements a light theme with white/light-grey grounds and dark text, moves the style picker to a left-hand sidebar that scrolls with the page, displays all 31 cartoon styles in a showcase on the landing pages, and creates a second root layout for English so `/en` renders with `<html lang="en">`.

The light theme is built on six CSS custom properties in `:root` of `app/globals.css`: a light background, dark text, secondary muted text, link/accent text, and button accents (kept unchanged at `#7c8dff` and `#33d2ff`). Every text-on-background pair meets WCAG AA contrast (4.5:1 minimum). All colour literals moved out of component files into `:root`, enforced by criteria 4 and 6.

The workbench is restructured into four sections in vertical order: KVKK notice, upload area, left sidebar of styles, and on the right a sticky result panel (on wide screens). The style sidebar is no longer sticky; it scrolls with the page. Cards on wide screens are larger (base floor raised to at least 190 px).

The landing showcases all 31 styles below the gallery. Web-optimized 480×480 px WebP copies of the style previews are generated once by `scripts/resize-style-previews.mjs` using `sharp` at quality 72, stored in `public/styles-web/`, and recorded in `lib/style-web-manifest.json` with SHA256 hashes proving derivation from the frozen preview files. Total size of 31 web copies: 1 204 102 bytes. The picker card switches to reference these smaller copies instead of the 1024 px originals, keeping lazy-loading.

Two root layouts replace the single root at `app/layout.tsx`. Route group `app/(tr)/` holds the Turkish root and landing pages with `<html lang="tr">`. Route group `app/(en)/` holds an English root and `/en/` and `/en/workshop` routes with `<html lang="en">`. This reverses task 0007 §4's one-root-layout decision. The cost, stated in the spec, is that switching language causes a full page load and drops any chosen photograph (but it is not persisted anyway, per the KVKK notice). Within one language, `/` to `/workshop` remains a client-side navigation that keeps it.

Legal and contact pages move to `app/(tr)/(legal)/` and `app/(tr)/contact` byte-identical to their source locations. The builder checked for the not-found issue mentioned in spec §3.4; the build prerendered `/_not-found` and the verifier confirmed no missing pages.

The builder's write of `scripts/resize-style-previews.mjs` was refused by scope (the spec allocated it only to the build phase), so the builder escalated. The operator then authorized the main session to write and run the script, producing 31 web copies and the manifest. The builder's inline run was compared to the operator's run and produced identical outputs. This instance of script authorship is recorded in a queued system finding (amended entry 35).

Accessibility preserved: four style groups with legends stay, the notice comes before every file input in both DOM and screen-reader order, and no CSS `order:` property reorders content.

## Key design decisions

**Light theme tokens.** All colours declared once in `:root`. `--accent` and `--accent-2` kept unchanged (`#7c8dff` and `#33d2ff`), as the button's gradient background; the button text is `--on-accent` (`#02142d`), and criterion 5 requires it and `--text` to reach 4.5:1 on both accents. `--bg` must have relative luminance ≥ 0.8 and `--text` ≤ 0.05. Every text on every surface pair verified at 4.5:1 minimum by criteria 5 and 6 (source-level, not runtime styles).

**Two root layouts, reversing task 0007 §4.** Next.js renders `<html>` in the root layout, which cannot read the path. Three options exist: (A) two root layouts by route group (proposed; the choice); (B) middleware reading headers (every page dynamic, no prerender); (C) client-side `document.documentElement.lang` (server HTML still wrong). The operator chose A. The cost: switching language is a full page load and drops a chosen photo. Nothing persists the photo to work around this, because the KVKK notice says it is not stored. Spec §13 item 1 states both the choice and the cost, acknowledged by approval.

**Web copies at 480 px, quality 72.** The spec (§5) measured 1 204 102 bytes for all 31 files at this size and quality, with the largest at 95 946 bytes. A per-file cap of 100 000 bytes holds. This supersedes task 0008 criterion 11's reference to `/styles/` in the picker; the intent (one directory, no fallback) is kept.

**Showcase replaces `.group-intro`.** The showcase renders five headings (one for each group plus "Default"), 31 images with names and descriptions, all in the visitor's language. Grid layout `repeat(2, 1fr)` on mobile, `repeat(4, 1fr)` from 900 px, with no numeric `minmax()` (criteria 8 reserves the first numeric minmax for `.style-grid`). Two i18n keys removed from both dictionaries together (criterion 19 checks parity).

**Workbench split into four blocks.** Order in DOM (and narrowscreen): notice, upload, styles sidebar, result. On 900 px+: two columns. Sidebar in column 1, upload and result in column 2. Result sticky from top. No picker `max-height` or `overflow` (it scrolls with the page). Group legends kept. No `order:` property anywhere (criterion 14 enforces DOM order).

## Remarks on criterion design

**Criteria 4, 5, 6 compute contrast from source CSS tokens.** They extract the `:root` block, parse token definitions, compute relative luminance from opaque hex values, and check every text token on every surface token. They do not measure a browser's computed styles; the spec (§4) notes this is source-level checking and names the operator's eyes as the place browser rendering is verified.

**Criterion 7 verifies workbench order and layout.** It checks DOM source order (not rendered position, which `flex-direction: row-reverse` could defeat), then checks that the media query sets the grid and that sticky positioning is on `.workshop-result` only.

**Criterion 8 locates `.style-grid` by rule name and measures its floor at every width.** The first numeric `minmax()` in the file must be inside `.style-grid` (criterion 8 needs it, task 0004 criterion 11 depends on it). Task 0007 moved `.group-preview` below `.style-grid` to fix this; criterion 8 confirms the floor by name rather than position.

**Criterion 11 walks the built HTML, finds `.style-showcase`, counts 31 images, and verifies each is lazy, sized, and alt-texted.** It also scans visible text for all 31 style names and descriptions and group headings in the page's language.

**Criteria 4, 5, 6 and 8 were proven both directions on a synthetic fixture** (spec §11.1): a handwritten light-theme CSS (tokens, gradient button, minmax floors) passed all four criteria, and four broken variants each turned the right criterion red.

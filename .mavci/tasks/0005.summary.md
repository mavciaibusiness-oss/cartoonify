## Execution summary

This task restructures the page layout to make the upload control the first element a visitor sees. The style picker and image display move into a two-column workbench that appears only after an image is chosen. No logic changes; the form validates, routes, and calls the provider identically to before.

**Layout states, controlled by `data-stage` derived from `previewUrl`:**

1. **Empty stage (`data-stage="empty"`)** — before any image is chosen: the upload control stands alone. The style panel, convert button, and gallery are all hidden with `display: none`. The KVKK transfer disclosure moves above the upload control, so the visitor reads where their photograph is going before uploading it.

2. **Chosen stage (`data-stage="chosen"`)** — after an image is selected: `.workbench` becomes visible as a grid:
   - Mobile-first (default): one column, preserving document order — upload first, then styles, then image and button
   - From 768px: left column holds the style picker (bounded by `--style-col-min: 180px` and `20rem` max-width), right column holds the chosen image and convert button
   - Gallery below the workbench in both cases

The task does not alter the picker's design, the card layout, the four groups, or the swatch fallbacks—all task 0004 artifacts ship unchanged. Three criteria explicitly guard against improving them in passing.

## Remarks on criterion design

**Criterion 1 pins the plugin version by literal path** (spec §8.1 item 5). Reading `ci_pinned_plugin_version` from the control plane and using that value in the same command is refused by the risk guard. The gate's own failing direction is unproven — only the version guard is. A plugin upgrade will fail criterion 1 and force a new spec, making the version decision visible rather than silent.

**Criterion 8 tests source order, not rendered geometry** (spec §8.1). The real claim — "the convert button sits beside the image in the rendered layout" — requires browser observation. A criterion needing a browser does not run. The operator should verify the rendered page visually before accepting this task.

**Criterion 9's numeric scan skips non-numeric `minmax` expressions** (spec §8.1 item 3). The first draft reported `NaN` against a correct stylesheet with the 768px rule placed above the 375px grid. This version scans for `minmax(` followed by digits and correctly measures the grid's floor of 150px against the column minimum of 180px.

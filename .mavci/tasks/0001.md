- **Task id:** 0001

- **Phase written in:** plan
- **Standards packs in force:** `nextjs-app-router`, `legal-tr-kvkk`

## 1. What is being built

A public, single-page image utility. The visitor picks an image, sees it previewed
in the browser, presses **Karikatüre Çevir**, and the image is POSTed to a
server-side route that calls the OpenAI image API. The cartoon comes back and is
shown beside the original with a download button.

No authentication. No accounts. No database. No object storage. No file is written
to disk at any point, on the client or the server. The uploaded bytes exist in
request memory, are forwarded to OpenAI, and the response bytes are returned inline
to the browser. Nothing survives the request.

The UI is Turkish.

**Nothing beyond the list above.** No rate limiter, no analytics, no history, no
gallery, no share links, no test runner, no new npm dependency.

## 2. The three decisions this spec makes explicitly

### 2.1 Tenancy

**This task touches zero tables and creates none.** There is no database
(`stack.db: "none"`), no tenant concept, and therefore no tenant column and no RLS
policy to write. `supabase-multitenant-rls` is not in `standards.packs` and must not
be reintroduced. See ADR 0001 for why `tenancy.model: "single-tenant"` in the
manifest overstates the truth: there are zero tenants, not one.

Every visitor is anonymous and identical. There is no per-visitor state of any kind,
including no cookie and no session.

### 2.2 Trust boundary

| Runs where | What | Sees `OPENAI_API_KEY`? |
|---|---|---|
| Browser | `components/cartoonify-form.tsx` — file picker, client-side preview and validation, fetch, result states | **Never** |
| Browser | `app/page.tsx`, `app/layout.tsx` — server-rendered shell and metadata | **Never** |
| Server | `app/api/cartoonify/route.ts` — the only OpenAI caller | Yes, via `getEnv()` |
| Server | `lib/env.ts` — the only file permitted to read `process.env` (`next.env_centralised`) | Yes, it is the source |
| Both | `lib/image-constraints.ts` — MIME allow-list, byte ceiling, magic-byte sniffer. Pure constants and pure functions, no secrets, safe to bundle client-side | No |

The key is not `NEXT_PUBLIC_`-prefixed and must never become so. `lib/env.ts` must
never be imported by a client component: its zod schema contains the literal string
`OPENAI_API_KEY`, so importing it client-side would emit that string into
`.next/static`, which criterion 6 detects.

The image itself crosses to a third country. That is a KVKK Art. 9 *yurt dışına
aktarım* and the visitor must be told at the point of upload, not only on `/kvkk`
(criterion 25).

### 2.3 Reversibility

Fully reversible. No migration, no schema, no external account change, no
infrastructure. Reverting the commit restores the current gate-green tree exactly.
The only irreversible side effect in the whole feature belongs to the operator, not
to this task: setting `OPENAI_API_KEY` in the Vercel project.

## 3. The constraint that shapes everything: there is no API key

`OPENAI_API_KEY` **is not set in this environment** and will be supplied by the
operator later. This is a stated constraint, not an oversight.

Consequences the builder must design for rather than work around:

1. **The build must succeed with no key.** `lib/env.ts` already parses lazily for
   this reason. Do not move `getEnv()` or `new OpenAI(...)` to module scope
   (criteria 3 and 10).
2. **The missing-key path is a product behaviour with its own HTTP status, error
   code and Turkish message** — not a crash, not a 500, not a stack trace. It is the
   single most-tested path in this spec (criterion 12).
3. **File validation runs before the key check**, so every validation failure mode
   is observable today without a key (criteria 11, 13, 14, 15). This ordering is
   deliberate and is itself an acceptance criterion.
4. Exactly one criterion (32) requires a live key. It is marked
   **OPERATOR-VERIFIED-AFTER-KEY** and must not block the verifier.

> `route.mjs:130 hasSpec()` runs `String(specText).includes(REVIEW_MARKER)` over
> the whole spec body, unanchored, and on a hit concludes the spec is "watermarked,
> not written". A spec that merely *quotes* the marker is therefore reported as

> back to the plan phase forever. This project cannot state its own gate

> Filed as **system finding 3** in `.mavci/lessons/pending-system-change.md`.
>
> So every place this spec would have written the literal, it derives it:
>
> ```bash
> MARKER="$(printf 'REVIEW%sREQUIRED' ' ')"
> ```
>
> `$MARKER` expands to exactly the string the checker emits, so criterion 1 stays
> mechanically checkable. The circumlocution is load-bearing: restoring the plain
> string would silently deadlock the chain again, and the next reader would have no
> way to tell why. Leave it.

## 5. Contracts

### 5.1 `lib/image-constraints.ts`

Single source of truth, imported by both the client component and the route.
Neither of those two files may restate a MIME string or a byte number of its own.

```
ALLOWED_MIME_TYPES = ['image/png', 'image/jpeg', 'image/webp']  (readonly)
MAX_FILE_BYTES     = 4 * 1024 * 1024                            // 4194304
sniffImageType(bytes: Uint8Array): 'image/png' | 'image/jpeg' | 'image/webp' | null
```

`MAX_FILE_BYTES` is 4 MiB because Vercel caps a serverless function request body at
4.5 MB. A larger ceiling would pass locally and fail only in production — the worst
available failure mode. Do not raise it.

`sniffImageType` reads magic bytes: PNG `89 50 4E 47 0D 0A 1A 0A`, JPEG `FF D8 FF`,
WebP `52 49 46 46` at offset 0 with `57 45 42 50` at offset 8. It exists because the
`type` on a `FormData` file is supplied by the client and is not evidence.

Use array/`Set` membership for the MIME check. **Do not build a `RegExp` from a
template literal** (`next.regex_no_template_literal`).

### 5.2 `POST /api/cartoonify`

Request: `multipart/form-data`, one field named `image`.

Route file must declare, at module scope:

```ts
export const dynamic = 'force-dynamic'   // next.route_force_dynamic
export const runtime = 'nodejs'
export const maxDuration = 60
```

Only `POST` is exported. No `GET`.

**Handler order, which is normative:**

1. Reject on `Content-Length` > `MAX_FILE_BYTES + 65536` → 400 `FILE_TOO_LARGE`
2. Parse the form; no `image` field or not a file → 400 `NO_FILE`
3. `file.size > MAX_FILE_BYTES` → 400 `FILE_TOO_LARGE`
4. `file.type` not in `ALLOWED_MIME_TYPES` → 400 `INVALID_TYPE`
5. `sniffImageType(bytes)` returns `null` or disagrees with `file.type` → 400 `INVALID_TYPE`
6. `hasOpenAIKey()` false → **503** `MISSING_API_KEY`
7. Construct the OpenAI client **inside the handler** with `getEnv().OPENAI_API_KEY`,
   call the image edit endpoint, request base64 output
8. Any thrown error or empty result → **502** `UPSTREAM_ERROR`
9. Success → **200**

Responses are always `application/json` with `Cache-Control: no-store`.

```jsonc
// 200
{ "ok": true, "image": "data:image/png;base64,<bytes>" }

// 400 / 502 / 503
{ "ok": false, "code": "<CODE>", "message": "<Turkish, user-facing, fixed constant>" }
```

`code` is one of `NO_FILE`, `INVALID_TYPE`, `FILE_TOO_LARGE`, `MISSING_API_KEY`,
`UPSTREAM_ERROR`. `message` is a fixed Turkish constant per code. **No upstream
error text, no `err.message`, no stack, no key name reaches the response body**
(criterion 16). Log detail server-side if useful; never return it.

**Why the `MISSING_API_KEY` message must not name `OPENAI_API_KEY`** — recorded
because the obvious "improvement" is to tell the user exactly what is missing, and
a later reader will otherwise make that change believing it is a kindness.

A 503 that names the variable **tells an attacker what to look for and tells the
user nothing they can act on.** The visitor is an anonymous member of the public
with no server access; naming the key cannot help them, because there is no action
it unlocks for them. The only reader it informs is one probing the deployment for
which provider and which credential to target, and it confirms both in a response
that requires no authentication to obtain.

So the split is deliberate and asymmetric: the *operator-facing* fact (the key is
unset) belongs in the server log, and the *user-facing* message says only that the
service is temporarily unavailable and to try again later. Criterion 12 enforces
this by asserting the substring `OPENAI_API_KEY` does not appear in the body.
The machine-readable `code` field still says `MISSING_API_KEY`, which is what the
UI switches on — the code is a contract, the message is copy, and only the message
is public-facing prose.

Do not "fix" this by adding the key name to the message. Change criterion 12 first,
with a reason, or leave it alone.

### 5.3 `components/cartoonify-form.tsx`

`'use client'` on line 1. State machine:

```ts
type Status = 'idle' | 'loading' | 'error' | 'success'
```

The root element carries `data-state={status}`. Rendering per state:

- **idle** — file input, the KVKK transfer notice (§5.4), disabled submit until a
  file is chosen; once chosen, the client-side preview via `URL.createObjectURL`
- **loading** — a busy indicator, submit disabled, the preview still visible
- **error** — the Turkish `message` from the JSON body, submit re-enabled so the
  visitor can retry
- **success** — original and result side by side, plus an
  `<a download="karikatur.png" href={dataUrl}>` download button

Client-side validation runs before the fetch, using `ALLOWED_MIME_TYPES` and
`MAX_FILE_BYTES` imported from `lib/image-constraints`, and produces the same
Turkish messages as the server codes. The server re-validates regardless; the
client check is a courtesy, never the control.

Every object URL created is released with `URL.revokeObjectURL` on replacement and
on unmount.

### 5.4 The KVKK notice, at the point of upload

Rendered inside `components/cartoonify-form.tsx`, adjacent to the file input,
visible in the `idle` state with no interaction. It must state, in Turkish:

- the image is sent to **OpenAI**
- servers are in the **ABD (Amerika Birleşik Devletleri)** — an explicit
  **yurt dışına aktarım**
- the image is **not stored** by this site, neither before nor after processing
- a link to `/kvkk` for the full aydınlatma metni

This is an Art. 10 disclosure obligation and burying it on `/kvkk` alone does not
discharge it. See ADR 0001: no storage removes the retention clause and nothing
else; the transfer disclosure is the dominant part of this product's KVKK surface.

### 5.5 SEO and responsive

`app/layout.tsx`: Turkish `title` and `description`, `metadataBase` set to
`https://cartoonify.vercel.app` (matching `deploy.site_url`), an `openGraph` block
with `locale: 'tr_TR'`, and an `export const viewport`. `<html lang="tr">` stays.

`app/globals.css`: the comparison container is a single column by default and two
columns from `768px` up, via a `@media` query. No horizontal overflow at 375px.

## 6. Acceptance criteria

Every criterion below is checkable **without an OpenAI API key**, except number 32,
which is explicitly marked and must not block the verifier.

Commands assume a bash shell at the repository root, and for the HTTP criteria a
server started with **`OPENAI_API_KEY` unset**:

```bash
npm install && npm run build && npm run start   # http://localhost:3000
```

Fixtures used by the HTTP criteria (written outside the repository):

```bash
T="${TMPDIR:-/tmp}/cartoonify-fixtures"; mkdir -p "$T"
node -e "const fs=require('fs'),h=Buffer.from([0x89,0x50,0x4e,0x47,0x0d,0x0a,0x1a,0x0a]);fs.writeFileSync(process.argv[1],Buffer.concat([h,Buffer.alloc(1024)]))" "$T/px.png"
node -e "const fs=require('fs'),h=Buffer.from([0x89,0x50,0x4e,0x47,0x0d,0x0a,0x1a,0x0a]);fs.writeFileSync(process.argv[1],Buffer.concat([h,Buffer.alloc(5*1024*1024)]))" "$T/big.png"
printf 'hello' > "$T/fake.png"
printf 'hello' > "$T/note.txt"
```

`px.png` carries valid PNG magic bytes and is not a decodable image. That is
sufficient and deliberate: **no key-free criterion reaches step 7 of the handler**,
so nothing ever decodes it. Only criterion 32 needs a real photograph.

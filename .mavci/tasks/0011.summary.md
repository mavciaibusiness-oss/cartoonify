## Execution summary

This task restructures the workbench into an application shell with a fixed left panel and scrolling main area once a photo is chosen. The landing pages use a 1 440 px container (replacing 1 200 px). Style picker cards are fixed to be square. When a result is shown, it carries its own style's name; clicking another card offers to regenerate in that new style rather than changing the label of the old result.

**Container.** One CSS token `--page-max: 1440px` replaces the 1 200 px fixed width. `main`, `footer`, and `.site-header` use `width: min(var(--page-max), 100%)`. The legal pages and contact page remain readable at about 72 characters per line via `.prose { max-width: 72ch; }`, one rule in the stylesheet with no file edits required. The workbench opts out with `.workshop-page:has(.workshop-shell) { width: 100% }` from 900 px, becoming full-width.

**Square cards.** The cause of the tall, stretched card images was found in the source: `<img height="480"` as a presentational attribute beats `aspect-ratio: 1 / 1` in the CSS. `.style-card-preview` gains `height: auto`, matching three other image rules (hero, gallery, showcase). All four rules (`aspect-ratio: 1 / 1; height: auto`) are enforced by criterion 27: every rule with `aspect-ratio` must also declare `height: auto`.

**Result names its own style.** New state `resultStyleId` is set inside `handleSubmit` to the style that was **sent**, captured when the request is built. A new module `lib/workbench-state.ts` (32 lines, imports nothing) exports `resultPanel(input)`, which decides what the panel shows: when a result exists and the selection has changed, `showRegenerate: true` lights a button labelled with the new style. The button `regenerate-button` sits in the actions block, built from a template in `lib/i18n/tr.ts` and `en.ts`: `form.regenerate` contains `{style}`. Two new strings: `form.resultStyle: 'Sonucun stili:'` and `form.regenerate: '{style} stiliyle yeniden oluştur'` in Turkish, `'Result style:'` and `'Regenerate in {style}'` in English.

**Application shell (§6.4 of the spec, operator's second-revision decision).** This replaces the first revision's "two sticky blocks" design. The workbench becomes an application shell once a photo is chosen (the empty workshop is unchanged).

- **Wide screens (900 px+).** `.workshop-shell` is `grid-template-columns: var(--panel-w) minmax(0, 1fr)`, where `--panel-w: 360px`. The left panel (`.workshop-panel`) is sticky from top, `height: 100dvh`, scrolling inside itself if content exceeds the screen. It holds: the KVKK notice (compact type), the upload thumbnail and replace/remove buttons, the selected style (always the current selection), generate/download/regenerate buttons, and status text. `.workshop-actions` inside the panel is also sticky at bottom 0 so the buttons stay visible while the panel scrolls. The right area (`.workshop-main`, grid-column 2) scrolls with the page, holding the result (a 1:1 square) followed by the style cards. Pressing generate scrolls `.workshop-result` into view using `scrollIntoView({ behavior: scrollBehaviorFor(reduced) })`, where `scrollBehaviorFor(reduced)` returns `'auto'` under reduced motion, `'smooth'` otherwise. Both the query `'(prefers-reduced-motion: reduce)'` and the function live in `lib/workbench-state.ts` to avoid carrying a string literal flagged by criterion 18 (carried from 0010).

- **Narrow screens (below 900 px).** Everything stacks in DOM order, and the actions become fixed at the bottom: `position: fixed; bottom: 0; height: var(--action-bar-h)`. The body reserves padding for it with `body:has(.workshop-shell)`, so the last card and the footer do not hide beneath it. The notice still precedes the file input.

**Criteria carries 0010 forward.** Twenty of task 0010's 23 criteria are carried verbatim as 0011's 1–6 and 8–21 (0010's 1–6, 8–17, 19, 21, 22 and 23; spec §10). The other three are replaced (§11.1): 0010's 7 by 0011's new 7 (the application-shell order), 0010's 18 by 22 (frozen files) and 0010's 20 by 23 (scope and encoding). ## System findings

Two findings were filed by the main session on 2026-09-30, 57 before the build (07:22:10Z) and 58 after the verification (08:22:15Z), and are queued for decision (not applied):

**Finding 57 — Silent truncation: a criterion over 8 186 characters is cut without an error.** Git Bash on Windows (both the 46 992-byte launcher and the real MSYS bash) truncates arguments to `bash -c` past 8 186 characters. When the cut lands inside a quote, it exits 2 with "unexpected EOF"; when it lands between commands, the prefix runs and exits 0, yielding a false pass. The 0010 spec's unexplained joined-criterion error was this. The 0011 spec generator refuses criteria over 7 800 characters as a stop-gap. The retroactive audit (finding 57 addendum) measured all 174 criteria in `.mavci/tasks/0001–0011.md` and found none over 8 000. The longest is 0011 criterion 29 at **7 727 characters**. The fix is to pass criteria to bash on stdin or in a temp file instead of as `-c` arguments.

**Finding 58 — On a pass, criterion output is discarded, so browser measurements are not recorded.** The verdict for 0011 attempts stores only the command and status for passing criteria. Criterion 29 printed 17 lines and criterion 31 printed 1 line of position and element-size measurements; none appear in the verdict. 27 of the verdict's 31 evidence strings are exactly 500 characters, cut. The main session re-ran both criteria from the spec to obtain the measurements, which are quoted above as "re-run by the main session". The fix is to store full stdout in side files or prepend measurements to the evidence instead of the command.

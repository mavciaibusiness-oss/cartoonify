## Execution summary

This is a **build task** (spec §1–§2). It implements the data model for the twelve-category style system approved in task 0013, reducing active styles from 31 to 29 and adding an explicit `category` field to every style (spec §3.1–§3.2). Step A was implemented by the builder; step B (`scripts/check-styles.mjs`) was written by the main session with operator authority (spec §8, route A, same authority mechanism as task 0013).

**The category field.** Every style in `lib/cartoon-styles.ts` carries a new property `category: '<id>'` typed as `StyleCategory`, the twelve ids from task 0013 §4.1 in the approved order: cartoon, line, drawing, paint, print, paper, textile, sculpt, caricature, graphic, era, surface (spec §3.1). The field values equal `data/style-catalog-draft.json`'s `category` field for each id (criterion 35). `STYLE_CATEGORIES` is exported as an array literal in the order approved by the operator (criterion 35). Category names are added to both `lib/i18n/tr.ts` and `lib/i18n/en.ts` under a new top-level key `styleCategories`, typed to prevent missing keys (spec §3.3). The categories are not rendered in 0014 (criterion 41).

**The coordinate field survives.** `coords` stays on every record, byte for byte as at `f1a84c5` (spec §3.2). It is needed by today's group layout (`deriveGroup`), by the prompt closings (`closingFor`), and by the checker (`check-styles.mjs`). Retiring it would require either storing `group` by hand or changing the layout; both are out of scope.

**The merge: two styles removed, legacy ids redirected.** `cel-frame` and `combed-paint` records are removed from `STYLE_SOURCE`, leaving 29 active styles in today's order (spec §3.4). The two merged ids are stored in `MERGED_STYLE_IDS = { 'cel-frame': 'classic', 'combed-paint': 'thick-paint' }`. A new exported resolver `resolveCartoonStyleId(value)` returns an active id unchanged, returns a merged id's target, and returns `null` for anything else. The API route (`app/api/cartoonify/route.ts`, step 6 only) uses the resolver to accept legacy ids and redirect them to the target: the prompt sent upstream is the target style's prompt, byte for byte as at `HEAD` (criterion 43). No status code, error code, error text, or response shape changes (spec §3.4, criterion 38).

**Preview file cleanup (§3.6).** Four webp files are deleted: `public/styles/cel-frame.webp`, `public/styles/combed-paint.webp`, `public/styles-web/cel-frame.webp`, `public/styles-web/combed-paint.webp`. `lib/style-previews.ts` removes the two ids, leaving 29 ids in style order (criterion 40). `lib/style-web-manifest.json` removes the two entries, every other byte unchanged (criterion 40). `lib/preview-manifest.json` stays byte for byte as a spend record; the extra entries are ignored by the scripts (spec §3.6).

**Gallery caption change (spec §3.8, G1 approved).** The pet tile in the gallery keeps its image (`public/gallery/pet/cel-frame.webp`, a paid render and gallery asset, not a style preview). Its caption changes from the merged style's old name "Çizgi Film" / "Animation Cel" to the name of the target style: "Klasik Karikatür" / "Classic Cartoon". In `components/gallery.tsx` the caption is `styleText(getCartoonStyle(resolvedId), locale).name`, where `resolvedId = resolveCartoonStyleId(id)`. Criterion 20 confirms the caption; criterion 17 confirms the gallery id (spec §3.8).

**Workshop page meta description (spec §3.7).** `tr.meta.workshopDescription` and `en.meta.workshopDescription` change from stating 31 to stating 29. This is the page's meta description in the dictionary, not derived by a count. Both texts updated; criterion 41 verifies the change (spec §3.7).

**Script checker (spec §4, step B).** `scripts/check-styles.mjs` is modified with operator authority to verify the category system and merger. It now fails when: `STYLE_CATEGORIES` is not 12 unique slug ids; a `STYLE_SOURCE` record lacks a `category` or its category is not in `STYLE_CATEGORIES`; a `MERGED_STYLE_IDS` key is not a slug or is an active id, or a value is not an active id. It prints a per-category count line. Criterion 42 proves the script fails on each of five mutations (spec §8).

**What this task does not do.** This task does not render images, change the application layout, or add the 70 new styles from `data/style-catalog-draft.json` (all 0015+, spec §12). The picker and showcase keep the four groups, labels, and order and show 29 styles (the previous 31 minus the two merged); criteria 11 and 34 confirm the groups and order are unchanged. Nothing is re-rendered; the spend record is intact.

**The API works with legacy ids.** A request `POST /api/cartoonify` with the form field `style=cel-frame` or `style=combed-paint` is accepted, and the prompt sent upstream is the target style's prompt. Criterion 43 exercises all 29 active ids and the two legacy redirects against a local stub provider stubbed at `127.0.0.1:3941`, records the prompt sent to the stub, verifies the request is accepted (32 requests accepted: 29 ids, 2 legacy, 1 no style field), rejects 5 requests with 400 `INVALID_STYLE` (Cel-Frame, __proto__, nope, constructor, two style fields), and reaches nothing outside the stub (spec §3.4, §10 criterion 43).

**Criterion runs.** All 43 criteria executed at 2026-09-30T12:19:28Z. Per spec §10, criteria 1–34 are carried from task 0012 (26 byte for byte, 8 renewed: 9, 11, 16, 17, 20, 22, 23, 27).

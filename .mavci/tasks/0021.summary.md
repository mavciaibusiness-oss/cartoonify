## Decisions (spec §2, as written there)

- **D1. Redis missing.** Production fails closed. Preview and local use in-process counters, logged once per process as not shared. A configured Redis that errors fails closed in every environment.
- **D2. Refunds.** The IP-hour counter is never refunded. The daily counter is refunded on a moderation flag, on moderation failure, and on an image-edit failure. A request refused at the cap undoes its own increment.
- **D3. Window.** A fixed UTC hour, not a sliding hour. Across an hour boundary one IP can make up to 20 conversions in a few minutes. The daily cap bounds total spend at about $6 per day (300 × $0.02).
- **D4. 10 MB against 4 MiB.** The browser accepts up to 10 MiB and re-encodes to JPEG when the file is over 4 MiB or the long edge is over 2048 px. The server keeps its 4 MiB ceiling. A re-encoded PNG loses transparency.
- **D5. Test runner.** Node's built-in `node:test`, no new dependency; `package-lock.json` unchanged.
- **D6. IP and privacy.** The client IP is `x-real-ip`, else the first `x-forwarded-for` entry, else `unknown`. It is stored only as HMAC-SHA256 keyed with the Redis token. Keys carry an environment prefix.
- **D7. Turnstile.** Outside production, missing keys fall back to Cloudflare's test keys. In production a missing or test secret fails closed. `TURNSTILE_SITEVERIFY_URL` is ignored in production. The script loads only on the workshop, after consent is first ticked.
- **D8. English page link.** The en page links to `/terms#icerik-kurallari` with "(in Turkish)" in the link text.

The spec gives these decisions without separate rationale beyond the context in its §1. No rationale is added here.

## Execution summary

This is a **build task** (spec §1–§2) with two steps. Step A, the builder's, implements the brand, header, colours, clickable cards, and site address (spec §4, items 1–8). Step B, the main session's with operator authority, updates `.mavci/project.json` and `.mavci/backlog.md` (spec §4, step B, route A as in 0013 and 0014).

**Attempt 1 failed at criterion 50.** Criterion 50 checks the band at 1280×624 and 1920×984 pixels on `/`, `/en`, and `/#styles`, and at 375×667 on `/`, `/en`, and `/terms`. The failure was environmental: a `next dev` process, started outside the verification, overwrote `.next` while the criteria ran, so criterion 50's server lost its stylesheet (recorded in `.mavci/tasks/0015.json`). Within attempt 1's build, before any verdict, a rework pass fixed criteria 8 and 48 and made the selected-style line visible above the actions (1280×624: 554.8 vs 558.8 px; 1920×984: 662.8 vs 666.8 px) by lowering the preview to 30vh and tightening the wide panel's padding and gap. The code did not change between attempts. Attempt 2 passed; the environmental condition did not recur.

**The brand.** Every visible "Cartoonify" in the site's user interface becomes **"ProToolHub"** (spec §3.1). The tool itself is named **"AI Karikatür Atölyesi"** in Turkish and **"AI Cartoon Studio"** in English. The tool's name is added to `landing.badge`, `workshop.badge` and `form.badge` in both dictionaries; the brand name "ProToolHub" appears in `meta.siteTitle`, `meta.homeTitle`, `meta.workshopTitle`, `landing.lede`, `workshop.emptyLede`, `gallery.lede` and a new `header.brand` key. Four new menu keys are added: `header.home`, `header.workshop`, `header.styles`, `header.contact`, along with `header.navLabel` and two new gallery link labels `gallery.openSource` and `gallery.openStyle`. The legal pages (`app/(tr)/(legal)/**` and `app/(tr)/contact/**`) are not changed; their old "Cartoonify" reference is listed for the lawyer and backlog (spec §2.2). Criterion 44 verifies the 17 row changes in the dictionaries and no visible "Cartoonify" on the four main pages.

**Brand files, copied byte for byte.** `assets/brand/protoolhub-icon.svg` is copied to `public/brand/protoolhub-icon.svg`, and `assets/brand/protoolhub-icon-badge.svg` is copied to `app/icon.svg` as the site's favicon. Both copies preserve their C2PA metadata blocks unchanged (spec §3.2). Criterion 45 confirms the byte copies.

**The header strip.** A new client component `components/site-header.tsx` renders on every page above the main content, wrapped in a new `.site-strip` element. The strip spans the full width with a gradient background from turquoise (`--accent`, `#6cc9d1`) into pink (`--accent-2`, `#f48fb1`). It holds the ProToolHub icon (32×32 px), the "ProToolHub" text brand, a four-item menu (Home, Studio, Styles, Contact), and the language switch on the right. On wide screens (≥ 900 px) the menu is one row; on mobile it scrolls horizontally with `overflow-x: auto` on a separate row below the brand. The strip is sticky only on wide screens; on mobile it scrolls away. Links carry `aria-current="page"` when matching the current route. The showcase section gains `id="styles"` so that `/#styles` can anchor to it (spec §3.3, criterion 45). The strip's height is a new token `--header-h: 60px`. Criteria 29, 30, 31 and 32 measure the panel and actions under the band; criteria 45 and 46 verify the structure and colours.

**Colours: the logo's palette.** The tokens in §3.4's table are changed to values derived from the logo SVGs. Dark turquoise `#2a7f8a` from the icon-badge ring is darkened to `#1f6f79` to reach 5.13:1 contrast on all surfaces (the source value reached only 4.12:1 on the light turquoise disc). Light turquoise `#e3f4f5` from the disc becomes the new surface accent `--surface-2`. Pink `#f48fb1` from the icon bows becomes `--accent-2`. Text colours (muted, dark) shift toward teal. The palette maintains WCAG AA minimum 4.5:1 contrast on all text/surface pairs; criterion 5 computes all 19 pairs and verifies the lowest is 5.13:1. No literal colours exist outside `:root` (criterion 4). Two button gradient values are pinned by criterion 4: `--accent: #6cc9d1` and `--accent-2: #f48fb1`. Criterion 46 checks the band's gradient and text colours by name.

**Clickable gallery and showcase cards.** Gallery image tiles and showcase style cards become links. Gallery source ("Kaynak") tiles link to `/workshop` (or `/en/workshop`) with no style parameter. Gallery render tiles and showcase cards link to `/workshop?style=<id>`, where the id is resolved (so a merged style's tile links to its target). The pet's `cel-frame` tile, captioned "Klasik Karikatür" since task 0014, links to `?style=classic`. Links are built with Next `<Link>` elements wrapping the existing images and captions. Each link has a focus outline in `var(--accent-text)`. Gallery links carry accessible labels from the new `gallery.openSource` and `gallery.openStyle` keys. Criterion 47 verifies the links; criterion 49 tests them in a real browser with photographs uploaded.

**The workshop reads the address.** A new pure module `lib/style-query.ts` exports `styleFromQuery(value: string | null | undefined): CartoonStyleId`, which returns `resolveCartoonStyleId(value) ?? DEFAULT_CARTOON_STYLE_ID`. Merged ids (cel-frame, combed-paint) select the style they merged into. Only unknown values fall back silently to the default. The form's initial state is now `useState<CartoonStyleId>(() => styleFromQuery(searchParams.get('style')))` (spec §3.5). The hook `useSearchParams` is safe here because the form is rendered only when a photo exists, which never happens during prerender. The `/workshop` page stays static (criterion 13 and 39 prove this). Choosing a card later does not rewrite the address. The KVKK notice still appears before the file input (criteria 14 and 21 carried). Criterion 48 verifies the query module and form; criterion 49 uploads a photo and tests the form with various `?style=` values, including the merged ids.

**The site address from environment.** `lib/env.ts` now exports `DEFAULT_SITE_URL = 'https://cartoonify-steel.vercel.app'` and `siteUrl()`, which returns `process.env.NEXT_PUBLIC_SITE_URL` if set, otherwise the default. Both layouts (`app/(tr)/layout.tsx` and `app/(en)/layout.tsx`) call `const SITE_URL = siteUrl()` instead of hardcoding the old `https://cartoonify.vercel.app`. `app/robots.ts` and `app/sitemap.ts` call `siteUrl()` instead of writing literals. Canonical links on the four main pages, Open Graph meta tags, sitemap and robots.txt all use the address from this source. Step B (the main session with operator authority) updates `.mavci/project.json` `deploy.site_url` to the new default and removes the "`.mavci/project.json` `deploy.site_url` is wrong" item from `.mavci/backlog.md`, replacing it with an item for the lawyer about the legal pages (spec §3.7). Criterion 51 checks the built pages, sitemap, robots, the two files and that no other file embeds an address; §11.1 records it red on a build with a wrong address and green on the default.

**Workshop layout under the strip.** At ≥ 900 px, the `.workshop-panel` now has `top: var(--header-h)` and `height: calc(100dvh - var(--header-h))` (instead of `top: 0` and `height: 100dvh`), so it starts exactly under the strip and its sticky action buttons stay visible. `.landing-upload` moves to `top: calc(var(--header-h) + 1rem)`. `.workshop-result` gains `scroll-margin-top: var(--header-h)` and `.style-showcase` gains `scroll-margin-top: calc(var(--header-h) + 1rem)`, so neither scrolls behind the strip when anchored. Below 900 px, the band is not sticky and the layout is unchanged from task 0014. Criteria 29 and 30 are renewed to measure the new layout; criteria 31 and 32 are carried unchanged and re-run; criterion 29's test is 7,759 characters (within the 7,800 limit). All carry forward as passing.

**Deliberately unchanged:** the legal pages and `/contact`, element ids and API path (still `/api/cartoonify`), style data and previews, picker and showcase groups and order (still four groups), the KVKK notice placement before the upload (criterion 14, 21 carried). Step A touches no file outside `app/`, `lib/`, `components/` or `public/` except `CHANGELOG.md`. Step B touches `.mavci/project.json` and `.mavci/backlog.md` only (spec §8).

# Task 0012 — A panel-wide upload preview, and the default style as a badged first card

- **Task id:** 0012
- **Project:** cartoonify
- **Phase at writing:** plan
- **Depends on:** `f3a9faa`, task 0011 closed
- **Paid calls:** none
- **Carries:** all 31 of task 0011's criteria (§10)

---

## 1. What this task is

1. **The upload preview grows.** Today the workbench's left panel shows the
   photo as a 64 px square. It becomes as wide as the panel's content, keeps
   the photo's aspect ratio with no crop, and is capped by the viewport height
   so that generate and download stay in the panel's visible part at 1280×720.
2. **The one-card "Varsayılan" group goes.** This applies to the workshop
   picker and to the landing showcase. Klasik Karikatür becomes the first card
   of the first group's grid and carries a "Varsayılan" badge, whose text is
   the existing `form.defaultGroup` string. Group order and the other groups do
   not change.

3. **The showcase's group headings lose their counts** (operator, §13 item 4).
   The now-unused `landing.groupCount` key is removed from both dictionaries.

Nothing else changes. There is no new route, request, key, image or string.

## 2. What the source says (at `f3a9faa`)

- **The default group is synthetic.** `components/cartoonify-form.tsx` (line
  171) builds `galleryGroups` as
  `{ id: 'default', label: t.form.defaultGroup, styles: [classic] }` ahead of
  `STYLE_GROUPS`. `components/style-showcase.tsx` does the same, with
  `count: null`, so that heading has no count. Every other showcase heading
  shows `format(t.landing.groupCount, { n })` ("8 stil") in a
  `span.showcase-count`. `landing.groupCount` (`tr.ts:50`, `en.ts:44`) is used
  nowhere else: `grep -rn groupCount app components lib scripts` finds only
  `style-showcase.tsx:32` and the two dictionaries.
- **Carried criterion 15** allows the page only the numbers
  `1, 2, 3, 4, 8, 7` (7 and 8 are the group sizes). A "9 stil" heading would
  break it, and a heading reading "8" above 9 cards would be wrong. Hence
  §3.4.
- **`classic` belongs to no group, and must stay that way.** In
  `lib/cartoon-styles.ts`, `classic` has `coords: null`, so `deriveGroup`
  gives it `group: null`. `scripts/check-styles.mjs` (criterion 2) fails with
  `classic must stay outside the grid` if that changes. So the move is a
  display decision, not a data change.
- **The groups:** `STYLE_GROUP_ORDER` is `cizgi, boya, baski, kesme`, with 8,
  8, 7 and 7 styles (read from `STYLE_GROUPS`). The first group is `cizgi`, and
  with classic added its grid holds 9 cards.
- **The upload block** (`cartoonify-form.tsx` lines 194–218), in DOM order:
  - a head holding the `h2` and the controls (`label[for=replace-image-input]`
    "Görseli değiştir", and a "Kaldır" button);
  - the hidden file input;
  - `.workshop-upload-file`, which holds the thumbnail
    `img.workshop-upload-thumb` and the file name.
- **The thumbnail rule** is `.workshop-upload-thumb`:
  `64px × 64px; object-fit: cover`. It is a crop.
- **The criteria's upload photo** is `public/hero/before.jpg`, which is
  1024×1024 (square).

## 3. Decisions this spec makes explicitly

**3.1 The preview: `max-height: 35vh`.** The operator gave 35–40vh.
- 35vh is 218 px at 624 px of inner height, and 233 px at 667 px.
- The lower end of the range was chosen because the panel above the preview
  already holds the KVKK notice (about 7 lines at 360 px, 0011 §6.4). Every
  pixel the preview takes pushes the file name and the controls toward the
  sticky action bar.
- Criterion 33 accepts 30–40vh, so the builder can move within the operator's
  range without a spec change.

**3.2 The order in the upload block: title, image, file name, then the two
controls on one row.**
- "Görseli değiştir" and "Kaldır" act on the image, so they sit directly under
  it and its name, not above it in the head. The head keeps only the title.
- At the 360 px panel width, the two buttons fit side by side at about 150 px
  each (0011 §6.4's width table), so one row costs one button height.
- At 375 px the same row fits the stacked layout.

**3.3 The default card is a property of the style, not a group.** A new pure
module, `lib/style-display.ts`, exports two things:
- `displayGroups()`: the groups in `STYLE_GROUP_ORDER`, each with its styles
  from `STYLE_GROUPS`, and `DEFAULT_CARTOON_STYLE_ID` placed first in the first
  group.
- `isDefaultStyle(id)`.

The picker (`cartoonify-form.tsx`) and the showcase (`style-showcase.tsx`) both
render from `displayGroups()`. The card (`style-card.tsx`) and the showcase item
show `<span class="style-default-badge">{t.form.defaultGroup}</span>` when
`isDefaultStyle(style.id)`. `lib/cartoon-styles.ts` does not change (§2).

**3.4 The showcase headings carry no count (operator's decision).**
- The `span.showcase-count` and the `.showcase-count` rule are removed.
- `landing.groupCount` is removed from `tr.ts` and `en.ts` together, so
  carried criterion 18 (dictionary parity) holds.
- Carried criterion 15 is unchanged and still green: the page then shows none
  of 8 and 7, which is within its allowed set.

**3.5 Ready for a category filter, without one.** Groups stay derived from the
data (`STYLE_GROUPS`). The default is decided by `isDefaultStyle`, not by where
a card sits. A later filter can therefore narrow `displayGroups()` by group id,
and the badge travels with the card wherever it lands. No filter is added here
(§12).

**3.6 Tenancy, trust boundary, reversibility.**
- There is no tenancy.
- The trust boundary is unchanged: no request, route or key changes.
- Reverting the commit restores everything. There is no migration and no spend.

## 4. The preview

- `.workshop-upload-preview`: `width: 100%; height: auto; max-height: 35vh;
  object-fit: contain`. It is centred in its box, with the panel's own
  background around a letterboxed photo.
- `img.workshop-upload-thumb` and its 64 px rule are removed.
- The file name (`.workshop-upload-name`) sits under the image, on one line
  with an ellipsis if it is long.
- The controls sit in `.workshop-upload-controls` under the name, as two
  equal-width buttons. They keep the existing `label[for=replace-image-input]`
  and the remove button, so the hidden input and its handler do not change.

## 5. The default card

- The picker's fieldsets come from `displayGroups()`. There are four legends,
  and the first grid starts with classic.
- The showcase's groups come from `displayGroups()` too. There are four `h3`
  headings, with no count (§3.4).
- `.style-default-badge` is a small label placed over the card's image corner.
  It uses the existing colour tokens only, so carried criteria 4–6 (tokens,
  WCAG AA, checked pairs) apply to it unchanged.

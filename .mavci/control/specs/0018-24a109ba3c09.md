## 3. Decisions this spec makes explicitly

### 3.1 Pairs: prompt change or subject move, and which is cheaper

- A **subject move** is one render (about $0.022). It changes only the preview. It fixes the picker comparison, not the styles' results on a user's own photo.
- A **prompt change** is one or two renders (A, then B if A is rejected): $0.022–$0.044. It changes users' results too (§1).
- So a move is never more expensive. A prompt change is proposed only where the two styles look alike *in themselves*, not only because they share a subject.

| Pair | Why they look alike | Move cost | Prompt cost | Proposed |
|---|---|---|---|---|
| thick-paint / oil-pastel | the same saturated sunset; the media (impasto oil, waxy pastel) differ | $0.022 | $0.022–0.044 | **move** oil-pastel M → E |
| origami / papercraft | both are faceted paper animals; the styles themselves are close | $0.022 | $0.022–0.044 | **prompt** papercraft (glue tabs, gaps, cut card) |
| fabric-applique / knitted | the same golden pets; felt and knit differ | $0.022 | $0.022–0.044 | **move** knitted P → N |
| cross-stitch / woven-tapestry | the same sunset; grid and weave differ | $0.022 | $0.022–0.044 | **move** woven-tapestry M → E |
| mid-century / ukiyo-e / travel-poster | the same sunset; ukiyo-e itself has no Japanese woodblock character | $0.022 | $0.022–0.044 | **prompt** ukiyo-e, **move** mid-century M → P |
| mosaic / sand-art | the same sunset; stone and sand differ | $0.022 | $0.022–0.044 | **move** sand-art M → K |

**The new subjects were chosen so that no new same-subject pair appears in the category:**
- oil-pastel joins graphite-pencil and sanguine (E);
- knitted joins thread-work and batik (N);
- woven-tapestry is the only textile on E;
- mid-century is the only era style on P;
- sand-art joins stained-glass (K).

Subject totals move from K20 E20 P20 M20 N19 to K21 E22 P20 M16 N20.

### 3.2 The variants

- §4.5 is the table: for each of the 16 styles a body A and a body B, written for this task.
- The prompt sent is `body + ' ' + CLOSING[closing]`; the closing is unchanged.
- Bodies sit in the length band of their closing: 197–217 characters for `preserve`, 198–218 for `exaggerate` (check-styles).
- They are **subject-neutral**: they name no dog, cat, jug, fruit, tower, woman or man. Users send their own photos, so a prompt that names the preview's subject would mislead the model on every other photo (criterion 63 checks a word list).
- **What the variants change:**
  - The close-to-source styles get an explicit instruction that the whole image, background included, is made in the medium, and that no photographic texture remains.
  - stretched-caricature no longer asks for the *image* to be stretched (the 0017 render squeezed the canvas); it asks for the *drawn figure* to be elongated, and says not to stretch the image.
  - The caricatures name the exaggeration concretely.

### 3.3 Batches, choices and the order of work

1. **Batch 1** (priority 1): stretched-caricature A, mass-caricature A, mass-caricature EN, newsprint-caricature A.
2. **Batch 2** (priority 2): the 11 styles' A.
3. **Batch 3** (priority 3): ukiyo-e A, papercraft A, and the 5 subject moves (current prompt, new subject).
4. **Batch 4**: variant B of every style whose A was rejected in batches 1–3. It is derived from your rejections and covered by its own plan hash. If nothing was rejected it is empty and skipped.

**Each batch:**
1. `--plan` shows every prompt, subject and the plan hash.
2. You approve the plan by hash.
3. `--render`.
4. The results are shown side by side with the current preview.
5. You approve by result hash:
   - batches 1–3: `--accept n --result <hex> [--reject id,id]`. A rejected A goes to batch 4, a rejected move keeps its subject.
   - batch 4: `--accept 4 --result <hex> --choose id=A|B|keep,…` for every style in it.

`--only <id>.<variant>` re-renders one trial before acceptance, under the same ceilings.

**After the last acceptance:**
1. `--finalize` writes `reports/0018-choices.json`: per style, its kind (`prompt` or `move`), its choice (`A`, `B`, `S` or `keep`), subject, trial file and hash, and full prompt.
2. **Step D (the builder)** applies it to `lib/cartoon-styles.ts` (the chosen bodies) and `lib/style-previews.ts` (the moved subjects). Nothing else changes.
3. `--promote` refuses unless the code already equals every choice. It then copies each chosen trial file to `public/styles/<id>.webp` and records it: `task: '0018'`, `from_trial`, cost 0, because it is the same file. The 0017 record moves to `discarded`.
4. The resize (0010's script, unchanged), then `npm run check` and `npm run build`.

### 3.4 The English experiment

- mass-caricature's variant A is also rendered as a fully English prompt, its closing included. The comparison is then Turkish A against the same content in English.
- **It is never promoted.** All 99 prompts and the closings are Turkish, and a single English prompt would break that without a decision about all of them (0017's operator decision: Turkish).
- If English is clearly better, that becomes a finding: a separate task deciding the language of all prompts.
- `reports/0018-choices.json` records it as `promoted: false` (criterion 66).

### 3.5 The script (step B)

`scripts/render-trials.mjs` is new. The main session writes it: `scripts/` is outside the builder's scope, and `render-batch.mjs` (0017) is not changed.
- **Its data:** `data/prompt-trials-0018.json`, equal to the table in §4.5 (criterion 63).
- **What it keeps from `render-batch.mjs`:** the model, size, quality and WebP; the source hash check before every call; the stops on no usage, the wrong format or the wrong quality; one call per item with `maxRetries: 0`; the key only through `getEnv()`; every record written after every call.
- **Trial files** go to `assets/trials/0018/<id>.<variant>.webp`. They are never served (`public/` is not involved) and are committed as the evidence of each choice.
- **Records:**
  - `lib/preview-manifest.json` gets `trials` (one record per trial: file, sha256, subject, source hash, prompt hash, task `0018`, batch, plan hash, usage, cost) and `batches_0018` (result hash, decisions).
  - A re-rendered trial's old record moves to `discarded`.
- **Spend:** only `task: '0018'` records with a batch count toward $1.50. The 0017 spend is history.

### 3.6 Observation, not acted on

- 13 of the 21 items are "too close to the photo".
- All of them use the `preserve` closing, whose last words are "yalnızca çizim üslubunu değiştir" (change only the drawing style). That plausibly pulls material styles (clay, papier-mâché, embroidery, marbling) back towards the photograph.
- Changing it would change all 88 `preserve` prompts and every user's result. That is outside this brief; it is filed as a candidate (§13 item 7).

## 9. Why each part is safe

- **Money.**
  - No call without your plan hash.
  - No batch without the previous one accepted by your result hash.
  - $0.50 per batch and $1.50 for the task are checked before every call.
  - Worst case is about $0.83, with re-renders on top only within the ceilings.
- **Users.**
  - A prompt changes only if you choose A or B for it. `keep` leaves it as it is.
